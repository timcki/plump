Book cache cleanupWhat a book leaves on the SD card, and the settings path that removes it. Same sheet family as the reader menu and contents.

Everything one book writes. name_hash is fnv1a(filename), case-sensitive: the bundle is named from all 32 bits, the image directory from the low 28. Bookmarks hash their own key, case-folded, inside the cache; stats and titles are keyed by the filename itself. Only the first two are derived from the EPUB.

Five DU partials from the row to the freed bytes, each scoped to the sheet rectangle, and one more when Back closes it. No GC anywhere on the path: the sheet is plain BW, like Home, so nothing has to be neutralized on the way in or out. The settings row’s new total is painted in the same refresh that removes the sheet.

  1. Two scopes, never one. Rebuild cache deletes only what the EPUB can regenerate: the bundle file and the image directory. Forget book adds the bookmark slot, the stats file, and the Recent record if it names this book. A single “clear cache” that silently took the reading position would be the wrong default; one that left 2 MB of stale images behind would not be a clear.
  2. The size is the label. Every row that deletes something is priced in the same place, right-aligned, and the sum is on the settings row before the sheet is ever opened. The reason to be on this screen is bytes, so bytes are what the screen is made of.
  3. Only the irreversible arms. Forget takes a second OK behind a sentence that names the loss; Rebuild fires on the first. Arming everything trains the second press into a reflex and buys nothing.
  4. Sizes stream, the sheet does not wait. Sizing a book costs one file_size in BOOKS/ plus one iterate of its image directory. The picker opens immediately with rows in directory order, then reorders once measured, on the background budget the title scan already uses. A row that has not been measured reads measuring, never 0 B.
  5. Close before unlink. FAT will not delete an open entry, and the cached subdirectory handle in SdStorageInner::sub_handles counts as open: the image directory’s handle must be evicted before its own entry goes, and a directory only unlinks once empty. The reader is popped to Home before its book is touched, for the same reason the upload server closes a file before unlinking it.
  6. Whole book or nothing, per artifact. No partial-section surgery inside a bundle: the whole file goes and the next open rebuilds. Stopping mid-clear is safe for the same reason a power loss mid-cache is: nothing reads a bundle it cannot verify, and a missing file is just a cold open.
  7. Believe the card, not the clear. A finished clear zeroes its row so every total on screen is right at once, then re-measures that book to confirm it. A book that really is at zero leaves the list on that pass; one the user stopped, or one whose unlink failed, shows its real leftover instead of vanishing.

What this cost, and what it left open

Both scopes shipped. The two differ in exactly one way that matters: the bookmark slot and the stats file are the only per-book bytes on the card that no amount of re-reading the EPUB can reconstruct, so Rebuild fires on one press and Forget takes a second.

It lives in SettingsApp. No new AppId, no nav change: the sheet is state on the settings screen, and the manager draws it after the shared chrome the way it draws the quick menu, so the status bar and tab bar do not slice its edges. The 20-entry size table costs about 1.4 KB of .bss, which took the linker’s heap floor from 157K to 154K.

The settings model needed one new shape. Row::Item(SettingId) and SettingId::get/set are contracted onto SystemSettings, and a row that opens a surface has no value there. Domain::Action with an inert get/set keeps one cursor type for the list, at the price of a variant those two methods have nothing to say about.

Still open: a second entry point — Clear cache in the Library’s Menu sheet, acting on the highlighted book — would reuse the same book sheet and skip the picker. It is the faster path for the common case, and the settings row stays the one place that shows the total.
